## Looking Glass 怎么用：为什么只 ping 测试 IP 还不够

RackNerd 官方对 Looking Glass 的定义是双向测试面板。传统主机商只给一个测试 IP 和测速文件，你测到的只是「你 → 机房」这一个方向；Looking Glass 反过来还能从机房向你的 IP 发起 Ping、Traceroute 和 MTR。去程和回程走的路由经常不一样，国内用户对此应该深有体会——去程走 163 骨干、回程走另一条线的组合并不少见。

官方推荐的操作流程是这样的：

1. 打开候选机房的 Looking Glass 页面
2. 点击 "My IP"，输入框会自动填入你的公网 IP
3. 跑一次 Ping，记录平均 RTT
4. 对另外两三个候选机房重复，横向对比
5. Ping 结果异常偏高时，改用 MTR 看逐跳丢包出在哪一段
6. 下载 100MB 测速文件，估算实际吞吐量

一个很多人不知道的细节：Looking Glass 的输入框接受任意公网 IPv4。如果你的用户集中在某个固定区域，也可以填一个当地的已知 IP，测试机房到你用户所在区域的延迟。

## 测试结果怎么判断：延迟基准线

数字测出来了，好不好的标准如下：

- **200ms 以下**：美西机房到国内的成功线，线路算不错
- **高于 250ms**：大概率不适合日常使用
- **<50ms**：体感即时；**50–100ms**：多数 Web 应用无感；**>150ms**：交互式操作开始能感觉到延迟

几条常见的参照：洛杉矶到纽约约 40ms，洛杉矶到新加坡约 160ms，西欧到美东（阿什本、纽约、新泽西）约 70–90ms，澳新到美西约 140–160ms。

判断的时候别犯两个错。一个是纠结 5ms 级别的差异，人的感知区分不出来，Looking Glass 的作用是帮你避开 50ms 以上的错误选择，30ms 和 180ms 才是真实信号。另一个是只测一次下结论，尤其是国内用户，建议在自己的晚高峰时段（6–10 点）跑 MTR，那时的路由和丢包才代表你实际会得到的体验。

## 常见问题

**Q：只 ping 测试 IP 够吗？**

不够，但它是第一步。ping 测试 IP 只能反映你到机房这一个方向，建议再用 Looking Glass 跑一次机房到你 IP 的反向测试，晚高峰时段的 MTR 结果最接近真实体验。

**Q：拿到 VPS 后 IP 被墙了怎么办？**

72 小时内在控制面板自助更换，免费；超过 72 小时每次 $3。所以开通后第一时间测线路，不满意立刻换。

**Q：新加坡和法兰克福机房怎么测？**

目前没有公开测试 IP。新加坡需要下单后开工单确认，对延迟敏感的用途，选已有测试 IP 的机房更稳妥。

**Q：美西延迟多少算正常？**

150–200ms 属于正常范围，200ms 以下线路不错，超过 250ms 基本可以放弃这个机房。纽约等东海岸机房到国内普遍 250ms 起步。

**Q：RackNerd 口碑怎么样？**

第三方评价平台上好评集中在价格低和客服响应快；吐槽集中在晚高峰速度波动、特价套餐不退款、部分机房补货不及时。和本文讲的重点对得上：先测线路再下单，能避开大部分槽点。
